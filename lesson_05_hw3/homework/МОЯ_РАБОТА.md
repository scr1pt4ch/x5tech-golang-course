# Сервис уведомлений

Автор: Мирошниченко Александр

## Что делает программа

Сервис рассылает текстовое уведомление по нескольким каналам: email, push и дополнительно SMS. Каждый канал сначала проверяет, что текст не пустой, затем проверяет параметры (адрес, device id, номер телефона), и в случае успеха сохраняет сообщение в истории. `Dispatch` останавливается на первой ошибке, `SafeDispatch` обходит все каналы.

## Как запустить

Команды выполняются из директории `lesson_05_hw3`, где лежит `go.mod`. Go нужен версии 1.22 или новее.

```
go run ./cmd/notify # проверка сценариев

go test -v ./practice # тесты
```

## Проверенные случаи

1. **Успешная отправка.** `Dispatch` возвращает `nil`. В историях email и push появляется `Текст уведомления` с указанием своего канала.
2. **Пустой текст.** Отправка идёт в те же каналы, что и в первом случае. Email возвращает `ErrEmptyMessage`, `Dispatch` добавляет контекст `канал email:` и останавливается. `errors.Is` находит причину через обёртку. Обе истории остались такими же, как после первого случая: новая запись не добавлена, старая не удалена.
3. **Отсутствующая настройка.** Push без `DeviceID` возвращает `*SendError`. `errors.As` извлекает его из обёртки `Dispatch`, после чего видны поля `Channel = "push"` и `Reason = "не задан device id"`. История не изменилась.
4. **Паника одного канала.** `BrokenNotifier` паникует, `SafeSend` превращает панику в ошибку с причиной `ErrNotifierPanic` и текстом паники, `SafeDispatch` добавляет контекст `канал broken:` и переходит к следующему каналу. Следующий push получил сообщение `[push] Текст уведомления`.
5. **Дополнительно: третий канал.** `SMSNotifier` встраивает `BaseNotifier` и реализует `Send`, поэтому подходит под интерфейс `Notifier`. `Dispatch` и `SafeDispatch` менять не пришлось. SMS без номера возвращает `*SendError`, рассылка продолжается, а SMS с номером сохраняет сообщение.

## Обработка ошибок

**`Dispatch`** вызывает каналы по очереди и при первой ошибке прекращает работу. Он возвращает одну ошибку вида `канал <имя>: <причина>`, оставшиеся каналы не вызываются. Паника внутри канала в `Dispatch` не перехватывается.

**`SafeDispatch`** вызывает каждый канал через `SafeSend` и не останавливается ни после обычной ошибки, ни после паники. Он возвращает слайс всех ошибок в порядке каналов, без `nil`. При полном успехе длина слайса нулевая.

`errors.Is` и `errors.As` используются в `main` (функции `report` и `reportAll`).

`recover` стоит в отложенной функции внутри `SafeSend`, которая оборачивает ровно один вызов `Send`. Если бы `recover` стоял вокруг всего цикла в `SafeDispatch`, после первой паники цикл бы прервался и следующие каналы не были бы вызваны.
